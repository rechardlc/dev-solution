## Vibecode 需求迭代

在存量项目中做功能迭代时，先理解完整链路，再规划改造方案。已有文档与口头描述未必准确，必须以代码与上下文为准。

| 资源 | 说明 |
|------|------|
| [开发功能迭代](./vibecode/开发功能迭代.md) | 完整工作流：信息收集 → 上下文校验 → 迭代规划 → 测试用例 → 执行前检查清单 |
| [vibecode-iteration Skill](./vibecode/skills/vibecode-iteration/SKILL.md) | Cursor Agent Skill，对话中 `@vibecode-iteration` 引用；详细输出模板见 [reference.md](./vibecode/skills/vibecode-iteration/reference.md) |

工作流要点：

1. **信息收集** — 检索关键字、代码、接口、文档与测试，梳理从入口到落库的调用链。
2. **上下文校验** — 区分「已确认事实」与「待核实假设」，避免在错误前提上规划。
3. **迭代规划** — 输出影响范围、风险提示、测试用例与「必须改造 / 可选优化」优先级。
4. **用例验收** — 改造前盘点既有测试，改造后按 P0/P1 用例逐项执行。

## 使用说明

- 架构类方案：在 [`架构设计/`](./架构设计/) 下新增 `.md` 文件，并同步更新本 README 的「架构设计」表格。
- 迭代工作流：在 [`vibecode/`](./vibecode/) 下维护；Skill 变更时同步更新 `skills/vibecode-iteration/` 内文件。
- `.history` 为编辑器本地历史，已加入 `.gitignore`，不必纳入版本管理。

## 说明

- 文档描述的是**特定项目约束下的工程实践**，并非通用标准；落地前请结合自家架构与安全要求评估。
- 涉及加密、密钥、网关等章节，请先阅读各文档中的「安全边界」或「设计背景」再决定是否采用。
