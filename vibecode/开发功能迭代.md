# Vibecode 需求迭代工作流

> 在存量项目中做功能迭代时，先理解完整链路，再规划改造方案。已有文档与口头描述未必准确，必须以代码与上下文为准。

**Agent Skill：** [skills/vibecode-iteration/SKILL.md](./skills/vibecode-iteration/SKILL.md)（对话中 `@` 引用即可；详细模板见 [reference.md](./skills/vibecode-iteration/reference.md)）

## 一、信息收集

根据当前功能需求，主动检索并汇总以下材料：

- **关键字**：业务术语、模块名、配置项、路由名等
- **代码**：入口文件、核心函数、调用方与被调用方
- **接口**：API 路径、请求/响应结构、网关或拦截器规则
- **文档**：README、架构说明、接口规范、历史方案记录
- **测试**：已有单元测试、集成测试、E2E 用例及手工测试记录

收集完成后，要求模型基于上述材料**梳理链路关系**，输出：

- 请求从入口到落库的完整调用链
- 关键依赖（模块、服务、第三方、配置）
- 核心函数及其职责边界

## 二、上下文校验

**默认假设：用户提供的功能描述、文档片段或既有实现可能存在偏差。**

校验时重点关注：

- 描述与代码实际行为是否一致
- 是否存在文档未覆盖的分支、兜底逻辑或历史兼容代码
- 是否遗漏跨模块、跨端（Web / 小程序 / 后端）的联动
- 是否存在可能被忽视的边界：权限、加密、缓存、错误处理、并发

将「已确认事实」与「待核实假设」分开标注，避免在错误前提上规划改造。

## 三、迭代规划

在链路清晰、上下文校验完成后，输出结构化迭代计划，至少包含：

| 维度 | 说明 |
|------|------|
| **迭代建议** | 推荐改造路径、分步顺序与理由 |
| **影响范围** | 涉及的文件、模块、接口、配置及上下游依赖 |
| **风险提示** | 回归点、兼容性、性能与安全相关注意事项 |
| **测试用例** | 主流程、边界、异常与回归场景；标注自动化 vs 手工 |
| **改造优先级** | 区分「必须改造」与「可选优化」，并说明判断依据 |

### 改造优先级原则

- **必须改造**：不改动则无法满足需求、存在明显缺陷或安全风险
- **可选优化**：体验提升、代码整洁、技术债偿还；可延后或按需实施

规划阶段保留一定自主性：在风险可控的前提下，优先最小改动、可验证、可回滚的方案。

## 四、测试用例

改造前梳理测试，改造后以用例验收，避免「改完不知是否回归」。

### 4.1 既有测试盘点

- 检索与本次功能相关的测试文件与用例名
- 确认现有覆盖范围：哪些路径已测、哪些缺口需补
- 标注可复用的回归用例 vs 需新增的场景

### 4.2 用例设计维度

| 类型 | 关注点 |
|------|--------|
| **主流程** | 正常输入下的端到端行为是否符合预期 |
| **边界** | 空值、极值、权限边界、状态切换临界点 |
| **异常** | 非法参数、超时、依赖失败、并发冲突 |
| **回归** | 本次改动可能影响但未直接修改的上下游行为 |

### 4.3 用例输出格式

每条用例至少包含：**编号、场景、前置条件、操作步骤、预期结果、优先级（P0/P1/P2）、执行方式（自动/手工）**。

示例：

| 编号 | 场景 | 前置条件 | 步骤 | 预期结果 | 优先级 | 方式 |
|------|------|----------|------|----------|--------|------|
| TC-01 | 正常提交订单 | 用户已登录 | 填写必填项并提交 | 返回成功，订单状态为待支付 | P0 | 自动 |
| TC-02 | 未登录访问 | 无 token | 调用下单接口 | 返回 401，不创建订单 | P0 | 自动 |
| TC-03 | 历史订单列表 | 存在旧数据 | 打开订单页 | 旧订单仍正常展示 | P1 | 手工 |

### 4.4 与改造的关系

- **必须改造**对应的功能：至少覆盖 P0 主流程 + 关键异常
- **影响范围**内的模块：补充回归用例，优先自动化可稳定复现的场景
- 改造完成后：按用例逐项执行，未通过则不得视为迭代完成

## 五、执行前检查清单

- [ ] 已检索关键字、代码、接口、文档等关键材料
- [ ] 已梳理完整链路与核心依赖
- [ ] 已标注可能被忽视的分支与边界情况
- [ ] 已完成上下文校验，区分事实与假设
- [ ] 已输出含影响范围、风险与优先级的迭代计划
- [ ] 已盘点既有测试并列出 P0/P1 用例（含回归场景）
- [ ] 改造完成后已按用例验收
